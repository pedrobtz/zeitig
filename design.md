# zudate design (target: 0.1.0 on CRAN)

`zudate` brings the [TC39 Temporal](https://tc39.es/proposal-temporal/docs/) date/time model to R.
All date/time logic is delegated to the Rust crate [`jiff`](https://docs.rs/jiff) (0.2.x), which was
itself designed after Temporal and implements the same semantics (RFC 9557 strings, nanosecond
precision, time-zone-aware arithmetic, disambiguation rules, rounding modes, calendar-aware spans).
R code provides vectorised, R-idiomatic types and interop with base R; Rust does the arithmetic.

This document records the architecture and the decisions behind it. `roadmap.md` tracks delivery.

## 1. Goals and non-goals

Goals for 0.1.0

- Faithful Temporal semantics for the core types: `Instant`, `PlainDate`, `PlainTime`,
  `PlainDateTime`, `ZonedDateTime`, `Duration`, plus `Now`.
- Vectorised R classes that behave like ordinary R vectors: `length()`, `[`, `c()`, `rev()`,
  `sort()`, `unique()`, `is.na()`, data-frame columns, `saveRDS()` round trip.
- Nanosecond precision without floating-point drift.
- Round-trip conversion with `Date`, `POSIXct`, `POSIXlt`, `difftime`.
- Builds offline from a CRAN tarball on Linux, macOS (x86_64, arm64) and Windows (Rtools, x86_64;
  arm64 best effort), honouring the CRAN Rust policy.

Non-goals for 0.1.0 (see roadmap "After 0.1.0")

- Non-ISO calendars. `jiff` only implements the ISO 8601 (proleptic Gregorian) calendar, so
  `calendar` arguments are accepted only as `"iso8601"`.
- `PlainYearMonth`, `PlainMonthDay`. `jiff` has no such types; they can be layered on `civil::Date`
  later.
- Locale-aware formatting (`toLocaleString`). `jiff` offers `strftime`, which is enough for 0.1.0.
- User-defined or custom time zones beyond IANA identifiers and fixed offsets.

## 2. Architecture

```
R user code
  |  vctrs record vectors (plain R vectors: double/integer/character)
  v
R/*.R            constructors, S3/vctrs methods, argument normalisation, option objects
  |  .Call() through generated R/000-wrappers.R
  v
src/init.c       generated by savvy-cli; .Call registration + error trampoline
  |  C ABI (SEXP in, SEXP out)
  v
src/rust/src/    hand-written Rust: #[savvy] fns, columnar in/out, per-element jiff calls
  |
  v
vendored jiff    all date/time semantics, tzdb lookup, parsing, formatting, rounding
```

Three rules keep this simple:

1. **Rust is stateless.** Every `#[savvy]` function receives whole columns (R vectors), loops over
   elements, builds `jiff` values on the fly, and returns whole columns. No `jiff` object outlives a
   call. There are no external pointers in the public API, so values serialise, copy and subset like
   any R vector.
2. **R owns the vector semantics.** Length, recycling, `NA`, names, subsetting, concatenation,
   printing and data-frame integration are implemented once via `vctrs` (`new_rcrd`), not in Rust.
3. **Temporal defines the behaviour, `jiff` implements it.** When the two differ, `jiff` wins only
   if the difference is documented in this file (section 9). Otherwise R code adapts the call so the
   user-visible result matches the Temporal specification.

### Why savvy (not extendr or cpp11 + a C++ date library)

- savvy generates the full `.Call` boilerplate and R wrappers, has a small dependency footprint
  (`savvy`, `savvy-ffi`, `savvy-macro`, `cc`, proc-macro crates), and panics are converted into
  R errors rather than crashing R. The small footprint matters because every transitive crate is
  vendored into the CRAN tarball.
- `jiff` is the only mature Rust library whose data model is Temporal's; implementing Temporal over
  `chrono` or Howard Hinnant's `date` would mean reimplementing disambiguation, span rounding and
  RFC 9557 parsing by hand.

## 3. Data model

Each Temporal type is an S3 class built with `vctrs::new_rcrd()`. Fields are ordinary atomic
vectors; `NA` in any field marks a missing element. Field order is chosen so that vctrs' default
record ordering (lexicographic over fields) equals Temporal's `compare()`.

| R class            | Temporal type   | Record fields (type)                                                                 | jiff type            |
|--------------------|-----------------|---------------------------------------------------------------------------------------|----------------------|
| `zudate_instant`   | `Instant`       | `seconds` (double, integral, since 1970-01-01T00:00Z), `nanos` (integer, 0..1e9-1)   | `Timestamp`          |
| `zudate_plain_date`| `PlainDate`     | `year` (integer), `month` (integer), `day` (integer)                                   | `civil::Date`        |
| `zudate_plain_time`| `PlainTime`     | `second_of_day` (integer, 0..86399), `nanos` (integer, 0..1e9-1)                      | `civil::Time`        |
| `zudate_plain_date_time` | `PlainDateTime` | date fields + time fields                                                        | `civil::DateTime`    |
| `zudate_zoned_date_time` | `ZonedDateTime` | `seconds`, `nanos`, `tz` (character, IANA id or `[+hh:mm]` fixed offset)         | `Zoned`              |
| `zudate_duration`  | `Duration`      | `years`, `months`, `weeks`, `days`, `hours`, `minutes`, `seconds`, `milliseconds`, `microseconds`, `nanoseconds` (all double, integral, same sign) | `Span`               |

Notes

- `seconds` is a double because `jiff::Timestamp` spans roughly years -9999..9999, i.e. about
  ±3e11 seconds, well inside the 2^53 exactly-representable range. Rust validates integrality.
- `ZonedDateTime` stores the time zone identifier per element, as Temporal does. `jiff` resolves
  the identifier on each call; Rust keeps a per-call `HashMap<&str, TimeZone>` so a column with one
  distinct zone pays one lookup.
- `Duration` field ranges are those of `jiff::Span` (years ±19998, months/weeks/days i32-ish, time
  units i64). Construction validates the uniform-sign rule and the ranges in Rust and errors with
  the Temporal error wording.
- Temporal's `Instant` in JavaScript is a `BigInt` of epoch nanoseconds; we expose
  `epoch_nanoseconds()` as a character/`bit64`-free double pair only through helper accessors
  (`epoch_seconds()`, `epoch_milliseconds()`, and `epoch_nanoseconds()` returning a string) since R
  has no native 64-bit integer.

Why records rather than a single numeric with attributes (like `POSIXct`): a single double cannot
hold nanosecond instants exactly, and splitting into two integer-valued fields keeps every value
exact while staying copy-on-modify friendly.

## 4. Public API

Naming: snake_case, one constructor per type, and generic verbs prefixed with the type where
Temporal has a method. All functions are vectorised and recycle arguments with `vctrs::vec_recycle_common()`.
`NA` propagates element-wise and never errors.

### Constructors and parsing (`Temporal.X.from`)

| Temporal                              | R                                                            |
|---------------------------------------|--------------------------------------------------------------|
| `Instant.from(string)`                | `instant(x)` where `x` is character (RFC 9557 / ISO 8601)    |
| `Instant.fromEpochMilliseconds(n)`    | `instant_from_epoch(seconds =, milliseconds =, nanoseconds =)` |
| `PlainDate.from(obj|string)`          | `plain_date(year, month, day)`; `plain_date(x)` for character |
| `PlainTime.from(...)`                 | `plain_time(hour, minute, second, millisecond, microsecond, nanosecond)` / character |
| `PlainDateTime.from(...)`             | `plain_date_time(year, month, day, hour, ...)` / character   |
| `ZonedDateTime.from(...)`             | `zoned_date_time(year, ..., time_zone =)`; character with `[Zone]` suffix |
| `Duration.from(...)`                  | `duration(years = 0, months = 0, ..., nanoseconds = 0)`; ISO 8601 duration strings |
| `Temporal.Now.*`                      | `now_instant()`, `now_zoned_date_time(time_zone = NULL)`, `now_plain_date(...)`, `now_plain_time(...)`, `now_plain_date_time(...)`, `now_time_zone()` |

Every character constructor is a parser; `as_instant()`, `as_plain_date()`, etc. are S3 generics
with methods for character, base R classes and the other zudate classes.

### Accessors (`.year`, `.epochMilliseconds`, ...)

`temporal_fields(x)` returns a data frame of all fields. Individual accessors: `year()`, `month()`,
`day()`, `hour()`, `minute()`, `second()`, `millisecond()`, `microsecond()`, `nanosecond()`,
`day_of_week()`, `day_of_year()`, `week_of_year()`, `year_of_week()`, `days_in_month()`,
`days_in_year()`, `in_leap_year()`, `epoch_seconds()`, `epoch_milliseconds()`, `offset()`,
`offset_nanoseconds()`, `time_zone()`, `hours_in_day()`, `total()`/`abs()`/`sign()`/`blank()` for
durations. These are implemented in R from the record fields when trivial, in Rust otherwise.

### Arithmetic and comparison

| Temporal method              | R                                                                        |
|------------------------------|--------------------------------------------------------------------------|
| `x.add(d, {overflow})`       | `x + d`, `temporal_add(x, d, overflow = "constrain")`                    |
| `x.subtract(d)`              | `x - d`, `temporal_subtract(x, d, ...)`                                  |
| `x.until(y, opts)`           | `temporal_until(x, y, largest_unit =, smallest_unit =, rounding_increment =, rounding_mode =)` |
| `x.since(y, opts)`           | `temporal_since(x, y, ...)`                                               |
| `X.compare(a, b)`            | `<`, `==`, `sort()`, `order()`, via `vctrs::vec_proxy_compare()`; `temporal_compare(a, b)` returns -1/0/1 |
| `x.equals(y)`                | `temporal_equals(x, y)` (compares time zone id too, unlike `==` on `ZonedDateTime` which follows `compare`) |
| `x.round(opts)`              | `temporal_round(x, smallest_unit =, rounding_increment = 1, rounding_mode = "halfExpand")` |
| `x.with({...}, {overflow})`  | `temporal_with(x, year = , month = , ...)`                               |
| `x.withPlainTime(t)` etc.    | `with_plain_time()`, `with_plain_date()`, `with_time_zone()`, `with_calendar()` (iso8601 only) |
| `zdt.startOfDay()`           | `start_of_day()`                                                         |
| `zdt.getTimeZoneTransition(dir)` | `time_zone_transition(x, direction = c("next", "previous"))`         |
| `Duration.compare(a, b, {relativeTo})` | `duration_compare(a, b, relative_to = NULL)`                    |
| `d.negated()`, `d.abs()`     | `-d`, `abs(d)`                                                           |
| `d.total({unit, relativeTo})`| `duration_total(d, unit, relative_to = NULL)`                           |

Operators are provided through `vctrs::vec_arith()` so that `Instant + Duration`,
`Duration + Instant`, `PlainDate - PlainDate` (returns a `Duration` in days, as Temporal's `since`
with default units) and `ZonedDateTime - Duration` all dispatch correctly and errors for undefined
combinations use the Temporal error text.

### Conversion between Temporal types

`to_instant()`, `to_zoned_date_time(x, time_zone, disambiguation =, offset =)`, `to_plain_date()`,
`to_plain_time()`, `to_plain_date_time()`. `ZonedDateTime -> Instant` is exact; `Instant ->
ZonedDateTime` needs a time zone; `Plain* -> Zoned*` goes through disambiguation.

### Formatting and parsing

- `format(x, ...)` / `as.character(x)` implement `toString()` with Temporal's options:
  `fractional_second_digits = "auto"`, `smallest_unit`, `rounding_mode`, `offset = "auto"|"never"`,
  `time_zone_name = "auto"|"never"|"critical"`, `calendar_name = "auto"|"always"|"never"|"critical"`.
- `temporal_strftime(x, fmt)` and `temporal_strptime(string, fmt, class)` expose `jiff::fmt::strtime`.
- `print()` shows the Temporal string form; `pillar` methods make tibble columns readable.

### Interop with base R

| From              | To                                  | Notes                                                        |
|-------------------|-------------------------------------|--------------------------------------------------------------|
| `Date`            | `PlainDate`                         | exact                                                        |
| `POSIXct`         | `Instant`, `ZonedDateTime`          | uses `tzone` attribute or `Sys.timezone()`; sub-nanosecond doubles are rounded |
| `POSIXlt`         | `PlainDateTime` / `ZonedDateTime`   | field-wise                                                   |
| `difftime`        | `Duration`                          | units mapped to days/hours/minutes/seconds                   |
| `PlainDate`       | `Date`                              | exact                                                        |
| `Instant`, `ZonedDateTime` | `POSIXct`                  | lossy below microseconds; documented                         |
| `Duration`        | `difftime`                          | only when the duration has no calendar units                 |

Default time zone: Temporal's `Now` uses the system zone. We use R's `Sys.timezone()` (which honours
`TZ`) rather than `jiff`'s own system detection so results match base R inside the same session.

## 5. Options and enumerations

Every option is a string argument validated in R with `rlang::arg_match()` and mapped to a `jiff`
enum in Rust. Temporal spelling is used verbatim (camelCase strings) so documentation can be copied
from the Temporal docs.

| Option               | Temporal values                                                                           | jiff                                   |
|----------------------|-------------------------------------------------------------------------------------------|----------------------------------------|
| `rounding_mode`      | `ceil`, `floor`, `expand`, `trunc`, `halfCeil`, `halfFloor`, `halfExpand`, `halfTrunc`, `halfEven` | `RoundMode::*` (same set)       |
| `smallest_unit`/`largest_unit` | `year`, `month`, `week`, `day`, `hour`, `minute`, `second`, `millisecond`, `microsecond`, `nanosecond`, `auto` | `Unit::*`      |
| `disambiguation`     | `compatible`, `earlier`, `later`, `reject`                                                 | `tz::Disambiguation`                   |
| `offset`             | `use`, `prefer`, `ignore`, `reject`                                                        | `tz::OffsetConflict::{AlwaysOffset, PreferOffset, AlwaysTimeZone, Reject}` |
| `overflow`           | `constrain`, `reject`                                                                      | no direct enum; see section 9          |

## 6. Error handling

- All Rust entry points return `savvy::Result`. `jiff::Error` is converted with its message
  (e.g. `"parameter 'day' with value 31 is not in the required range of 1..=30"`); the R wrapper
  rethrows it as a condition of class `zudate_error` with the element index appended
  (`"... (element 3)"`) when a vector operation fails.
- Temporal distinguishes `RangeError` and `TypeError`. R conditions carry a subclass
  `zudate_range_error` / `zudate_type_error`; input-type problems are detected in R before calling
  Rust.
- `NA` is never an error. Rust receives `NA` as R's sentinel values via savvy's `is_na()` and emits
  `NA` fields in the output.
- Panics must be impossible on user input. `panic = "abort"` stays on for release builds (CRAN
  requirement that the package does not leave R in a corrupted state after a Rust unwind), so any
  `unwrap()`/indexing on user-controlled data is a bug.

## 7. Vendoring and CRAN compliance

The CRAN policy for Rust (https://cran.r-project.org/web/packages/using_rust.html) is the binding
constraint on the build. The scheme:

1. **Vendored sources.** `cargo vendor` runs against `src/rust/Cargo.lock` and the result is stored
   compressed as `src/rust/vendor.tar.xz` (in git, regenerated by `tools/vendor.sh`, which also
   refreshes `inst/AUTHORS` and `LICENSE.note`; the archive is deterministic, so re-running it
   without a lockfile change produces no diff). `src/Makevars.in` extracts it into
   `src/rust/vendor/` before `cargo build` with R's own `untar(tar = "internal")` (an `xz`
   binary is not guaranteed, e.g. the r-devel clang containers lack it), creates `src/rust/cargo-home/config.toml` redirecting
   `crates-io` to `vendor` (relative to the parent of `CARGO_HOME`, so no absolute or drive-letter
   paths), and runs cargo with `CARGO_HOME=src/rust/cargo-home` and `CARGO_NET_OFFLINE=true`.
   The committed `src/rust/.cargo/config.toml` (MSVC `cargo test` only) is left untouched.
   `cleanup` removes the extracted directory and the generated cargo home. The same path is used
   by `devtools::load_all()`, so every local build is already offline.
2. **Lockfile committed.** `src/rust/Cargo.lock` is tracked so builds are reproducible and the
   vendored set matches exactly. `Cargo.toml` pins `jiff` and `savvy` to explicit minor versions
   (no `"*"`).
3. **Dependency surface.** Keep it minimal because every crate's source ships in the tarball and
   counts toward the 5 MB CRAN size guideline. `Cargo.lock` is resolved with every optional
   feature of every dependency, so `cargo vendor` also ships crates that are never compiled
   (`defmt*`, `serde_core`/`serde_derive`, `log`, `thiserror*`, `bitflags`, `jiff-static` and a
   second `syn`); they cost about 0.3 MB compressed and are accepted rather than pruned by hand,
   because a pruned vendor directory no longer matches the lockfile. Measured (jiff 0.2.37,
   savvy 0.11.0): 29 crates, `vendor.tar.xz` 1.5 MB, source tarball 1.5 MB. Features on `jiff`: `std`, `tz-system`, `tz-fat`,
   `tzdb-zoneinfo` (read `/usr/share/zoneinfo` on Unix), `tzdb-bundle-platform` (bundled database
   only where the platform has none, i.e. Windows), `perf-inline`; `default-features = false`
   drops `tzdb-concatenated` (Android only), `serde`, `logging` and `jiff-static`.
4. **Time zone database.** On Linux/macOS `jiff` reads `/usr/share/zoneinfo` (or `TZDIR`). On
   Windows it uses the bundled `jiff-tzdb` because Windows has no zoneinfo. CRAN's check machines
   all satisfy one of these. `ZUDATE_TZDIR` is honoured as an override for testing. Document in
   the package that the database version therefore follows the OS on Unix and the vendored crate on
   Windows.
5. **Authorship and licences.** `DESCRIPTION` adds
   `person("The authors of the dependency Rust crates", role = "cph")`, `inst/AUTHORS` lists every
   vendored crate with authors and licence, and `LICENSE.note` summarises the licence mix (MIT,
   Apache-2.0, Unlicense for jiff). All are permissive and compatible with the package's MIT licence.
6. **Build constraints.** `cargo build -j 2` (CRAN limits to two cores), `--offline`, no network,
   no writes outside the build directory (`CARGO_HOME` is pointed inside `src/rust/` during the
   build so cargo never touches `~/.cargo`), cargo/rustc versions echoed by `configure`
   (already in place), `SystemRequirements: Cargo (Rust's package manager), rustc (>= 1.81)`
   (MSRV set by savvy 0.11; jiff needs 1.70; checked with `cargo +1.81 build --offline`), Rust
   edition 2021 (edition 2024 needs rustc 1.85, which older CRAN flavours may
   not have).
7. **Windows ARM64.** `configure.win` picks the target from `$(R CMD config CC) -dumpmachine`:
   `x86_64-pc-windows-gnu` (linker `x86_64-w64-mingw32.static.posix-gcc`) or
   `aarch64-pc-windows-gnullvm` (linker `aarch64-w64-mingw32.static.posix-clang`, best effort).
8. **Installed size.** The static library is deleted after linking (already done); release profile
   sets `opt-level = 3`, `lto = true`, `codegen-units = 1`, `strip = true`. `strip` does not apply
   to a `staticlib`, so the linked `zudate.so` keeps the debug info of the precompiled Rust
   standard library: about 6 MB on Linux, 2.3 MB after `strip --strip-debug`. We accept the
   installed-size NOTE rather than strip in Makevars (R's `--strip` install option and CRAN's own
   binary builds handle it).
9. **Package checks.** Zero `R CMD check --as-cran` warnings; the only tolerated NOTE is the one
   about the installed `libs` size if it appears. Tests and examples run well under a minute.
   `webR`/Emscripten support from the savvy template is kept but not promised.

## 8. Testing strategy

- **R unit tests (`tests/testthat/`)**, one file per type plus `test-arith.R`, `test-format.R`,
  `test-interop.R`, `test-vctrs.R`. Expectations are taken from the Temporal documentation examples
  and selected cases from the test262 Temporal suite (ported by hand into testthat; a script in
  `tools/` records their origin). Every option value and every documented error message has a test.
- **Property tests in Rust** (`#[cfg(test)]`): parse/format round trips, `add` then `since` identity,
  ordering consistency across the record representation and `jiff` comparison.
- **savvy integration tests** (`savvy-cli test`) for anything that needs a live R session, e.g. `NA`
  handling at the FFI boundary.
- **Platform matrix** via the existing CI (`pedrobtz/r-actions` with `rust: true`): Linux, macOS,
  Windows; the `full-ci` label or a push to `main` runs the full set. Add a job that installs from
  the built tarball with network disabled to prove the vendored build works.
- **CRAN rehearsal**: `rhub::rhub_check()` on the Rust-enabled images and `devtools::check_win_devel()`
  before submission.

## 9. Known deviations from Temporal (and how they are handled)

| Area | Temporal | jiff | 0.1.0 behaviour |
|------|----------|------|-----------------|
| Calendars | pluggable, `iso8601` default | ISO only | `calendar = "iso8601"` accepted, anything else errors with `zudate_range_error` |
| `overflow: "constrain"` in `from()`/`with()` | clamps day to month length | `civil::Date::new` rejects | R/Rust clamps `day` to `days_in_month` before calling `jiff` when `overflow = "constrain"`; `reject` passes through |
| Date arithmetic across month ends | constrain (Jan 31 + 1 month = Feb 28) | same | no adaptation needed |
| `Instant` range | ±1e8 days from epoch | ±9999 years (`Timestamp::MIN/MAX`) | jiff's range; documented; values outside error |
| `Duration` component range | up to 2^53 per unit | `Span` unit limits | jiff's range; documented |
| `Duration` string with fractional units | allowed on the smallest unit | allowed | same |
| `ZonedDateTime` equality | `equals` includes time zone id | `Zoned == Zoned` compares instant and zone | `==` follows `compare` (instant only); `temporal_equals()` also compares the zone id |
| `until`/`since` default units on `ZonedDateTime` | `hour` largest unit | `Zoned::until` defaults to hours as well | same |
| `toString()` fractional digits | `auto` trims trailing zeros | `Display` prints `auto` precision | same |
| Leap seconds | not represented | not represented | same |

Anything discovered later goes in this table before the behaviour is shipped.

## 10. Performance notes

- Per-call cost is one `.Call` plus an allocation per output column; per-element cost is a `jiff`
  operation (tens of nanoseconds for civil math, a few hundred for zoned math after the zone is
  cached). This is competitive with `clock` and far faster than `lubridate` for vector work.
- Parsing character vectors is done in Rust; R never splits strings.
- `ZonedDateTime` columns with many distinct zones pay one `TimeZone::get` per distinct id per call.
- No parallelism in Rust (CRAN restricts to two threads and `jiff` work is already cheap).

## 11. Open questions (decide before 0.1.0 feature freeze)

1. Whether `Duration` fields should be stored as doubles (chosen above, for range) or as integers
   with a separate overflow check; doubles are simpler and exact up to 2^53.
2. Whether `==` on `ZonedDateTime` should be `compare`-based (chosen) or `equals`-based.
3. Whether to export `SignedDuration` (jiff-only, absolute time). Leaning no: not part of Temporal.
4. Whether to ship `pillar`/`tibble` methods in 0.1.0 (Suggests) or defer.
5. Final function prefix: `temporal_*` (chosen) versus a shorter `tp_*`.
